# TaskBoard

Markdown-first desktop task boards for multiple projects. The original Wartribes board remains the default on first launch.

Default Wartribes board: `B:\GDrive\SharedWithPhone\Obsidian\jjj\Wartribes\Tasks`

## Project tabs

TaskBoard discovers existing `jjj\[ProjectName]\Tasks\_board.md` boards automatically, including boards created by agents. Tabs and board names refresh every two seconds and when the window regains focus; catalog changes from other windows are also picked up. Refresh waits while an editor, project dialog, drag, or operation is active and keeps the current project selected. Discovery reads metadata without changing task files or requiring registration in `projects.json`. Removing a tab remembers its path locally so discovery does not immediately restore it; adding that project again unhides it.

TaskBoard opens with a tab strip for individual projects. Click **+ Project** and use **Browse…** to select a source/working folder; the project name is suggested from the folder name and can be edited. **+ Add folder** associates multiple directories (such as code and assets) with the same project. A project’s tasks are automatically created or reused in `B:\GDrive\SharedWithPhone\Obsidian\jjj\[ProjectName]\Tasks`—there is no board initialization checkbox. The gear icon on an existing tab edits its associated folders without touching task data or moving source files. The selected tab and folder associations persist across restarts in `%APPDATA%\TaskBoard\projects.json`. Each tab isolates task state, drafts, undo history, queues, snoozes, refresh and board preferences; tabs are locked while an editor or an operation is active. Removing a tab never deletes any tasks or directories. The original Wartribes tab, files, and user preferences are preserved.

**CLI:** Other projects can already be accessed with `TaskBoard.exe --root "D:\Projects\Other\Tasks" --json task list`. For safety, the CLI default remains Wartribes rather than whichever desktop tab was last active. Each board may declare `task_prefix: T3` and `epic_prefix: T3E` in its `_board.md` YAML; both CLI and desktop then generate `T3-0001` / `T3E-0001`. Existing WT/WTE and earlier-prefix IDs remain accessible without renaming. The **+ Project** dialog suggests editable prefixes, and each tab's gear edits them later. Boards with no prefix fields (including Wartribes) retain WT/WTE defaults; workflow roles remain a future feature. See [multi-project groundwork and limitations](docs/MULTI_PROJECT_FOUNDATION_20261022.md).

The **New Task** dialog reserves and displays its eventual ID immediately; closing the dialog releases it without creating an empty card. **Ctrl+V** with an image in the clipboard inside any task editor attaches the image on Save under `Tasks/Attachments/<task-id>/`, adds an image link to Description, and shows a thumbnail; pasted text remains normal text. Images up to 20 MB (PNG/JPEG/WebP/GIF) are supported.

Tasks can be edited directly in Obsidian. The editor presents **Description** as an editable original brief followed by timestamped, read-only updates. Updates (including submitted **Note to AI** text) are stored inside the Markdown `## Description` section using quoted text and comment markers, so an update cannot accidentally become a new Markdown section. Historical `AI Notes` and `User Notes` remain readable for compatibility; saving in TaskBoard moves prior AI notes and submitted Note to AI text into the description history and clears those separate fields.

## Human app

Double-click `Open TaskBoard.cmd`, or launch `TaskBoard.exe` without arguments. The same `TaskBoard.exe` now also runs the agent CLI whenever arguments are supplied (`TaskBoard.exe --help`, `TaskBoard.exe --json task show WT-0158`); the desktop UI is launched only with no arguments.

Key interactions:
- drag cards between columns;
- drag a card onto another card to make it a subtask of that task;
- drag column headers to reorder columns without native browser drag/drop;
- click the ✓ in a non-terminal column header to mark/unmark that entire column as AI-ready;
- collapse columns and parent tasks; right-click any column (including its collapsed bar) for Rename, Archive all, and snooze for 1 day, 3 days, 1 week, or 1 calendar month; snoozed columns automatically reopen after the deadline, display a temporary sun/awake icon for 24 hours, and can be woken manually;
- right-drag empty board space to pan horizontally, or use the vertical mouse wheel over board/column whitespace to scroll horizontally; dragging a task or column header near either horizontal screen edge auto-scrolls the board until the drag leaves the edge or is released; card lists retain their normal vertical wheel scrolling;
- right-click tasks for Edit, Move to done, Move to... (column submenu), New subtask, Remove parent, clipboard copy (ID, ID + title, full Markdown file path, ready-to-paste agent execute message), Highlight in Fomni, Open in Obsidian, and Archive; bulk Archive all automatically unparents active children in other columns (preserving their work and allowing a single Undo);
- cards observed created, moved (including placement changes), or edited while TaskBoard is open gain a blue border for 10 minutes, with a hover timestamp; the indicator survives a window restart via local UI storage and does not change the Markdown task or add an Attention flag;
- tasks entering a terminal column such as Done receive a completion date and precise completion timestamp, clear their **For user** status (including legacy `needs-user`), appear at the very top (newest first, including cards completed by agents), and are automatically archived after 7 days; reopening them clears both timestamps;
- hover cards for a full preview including task ID, description and its update timeline, acceptance criteria, question, and any historical user/AI notes; previews dismiss quickly when leaving the card (unless moused into the preview to inspect it); title text is relatively light, and agents can bold selected title phrases using Markdown `**important words**` (rendered safely in card/hover, stored verbatim in Markdown);
- Refresh forces a fresh Markdown reload and confirms when finished; the board also refreshes automatically every few seconds while you are not interacting with it;
- click cards for full details, question answering, and an optional vector task-type icon (Bug, New feature, Refactor, Content, Validation, Design, Visual Work, Hard (complex implementation/integration/networking/deep refactoring));
- **Hard** is a task icon for substantial engineering complexity (deep integrations, networking, architectural changes, major refactoring); it does not change task scheduling or priority. Spawn creates a task-bound T3 implementation worker for an unclaimed executable task; existing linked sessions show Open Session instead.
- task icons are stored as optional `icon` values in Markdown frontmatter, and can also be set using the CLI `task create --icon` or `task update --icon` (`--clear-icon` to remove); the toolbar **Filters** panel combines icon (including no icon), column, readiness, task type, and attention filters; selections are ORed within a group and ANDed across groups, alongside text search;
- when agents inspect or claim `Visual Work` tasks, the CLI returns a non-blocking **Claude Opus only** advisory; `Design` tasks return a non-blocking Opus/Astra-only advisory for initial drafts (subsequent revisions are unrestricted);
- The yellow **User queue** top-bar button counts outstanding, unsnoozed **For user** tasks and opens them in the editor newest-first (creation date, then ID). **Skip** leaves the task untouched and moves forward; **Snooze 24h** likewise moves forward but temporarily removes the task from the queue and its count. Snoozes survive an app restart via local UI storage, automatically expire after 24 hours, and never edit the underlying Markdown task. **Save** persists edits and advances to the next queued task; changing the column to Done clears that task from the queue. **Close & Followup** in queue review opens the new follow-up for editing, then saving or closing that follow-up resumes the queued review where it left off. The pass ends quietly without a notice bar; Cancel/Escape on a queued task exits the pass, and skipped tasks remain available next time.
- `F1`–`F12` switch directly to the corresponding project tab, except while a modal/editor is open. `Ctrl+T` creates a task in the default AI Ready column; `Ctrl+S` saves/closes an open task (or saves and advances during User queue review); `Esc` closes it; `Ctrl+Z` undoes the last persisted board action when the editor is closed.

Attention icons:
- **? Question** — answerable user question; floats to top.
- **✎ UserNote** — you wrote/changed a Note to AI; floats to top until an agent handles it.
- **× Blocked** — cannot proceed; floats to bottom.
- **! Priority** — persistent golden border and badge. Toggle by right-clicking a card or from the editor. Actionable priority tasks sort ahead of ordinary ready work in the board and CLI discovery; agents should prioritize them while respecting dependencies.

The editor has a single human-authored **Note to AI** composer (the AI-only Add update tab is gone). The original Description and historical AI updates remain visible and editable/read-only respectively. The bottom **Done** button optionally creates a linked follow-up when the adjacent Follow-up checkbox is checked (off by default). The **Note to AI** field is a submission composer rather than a second permanent notes section: starting an instruction clears **For user** immediately in the editor, and **Save** appends it to the Description timeline with a timestamp, empties the composer, and raises `UserNote` for AI attention. **For user** is now the single human-input status in the UI and user queue; the old `NeedsUser` attention flag remains readable as a backward-compatible alias. New CLI `--attention needs-user` creations become For user cards. The independent AI Notes editor was removed; historical agent notes are displayed in the timeline and imported into Description on save.

New non-terminal columns automatically start AI-ready unless named Draft, Done, Blocked, or Review. Existing project boards were backfilled to the same policy on 2026-10-23, including In Progress. `AI Ready` is the default new-task column. Any non-terminal column can also be marked AI-ready with its ✓ control; Draft and terminal columns cannot. Task/board writes use SHA-256 content revisions plus a cross-process lock, so a concurrent Obsidian/agent edit is rejected as a conflict rather than silently overwritten.

## Epics and task dependencies

- **Task** (`kind: task`, normally `WT-####`) is an executable work unit an AI can claim and move. **Only epics can be parents.** Tasks and For user cards can be children of an epic but cannot have subtasks of their own. Epics are root-level containers, not nested within other tasks or epics.
- **For user** (`kind: for_user`, normal `WT-####` IDs) is **human-only work**: asset/mesh supply, animation references, playtesting, approvals, design decisions. It has a conspicuous **orange** card and FOR USER badge, and sorts toward the top of its column. Agents can create it and attach planning notes, but cannot claim it or finish/archive it through the agent CLI. A human completes it by moving it to Done in the TaskBoard app. The card can be a hard prerequisite (`depends_on`) for downstream AI implementation; `task list --ai-ready` omits all user-only tasks. When the human marks the card Done, its persisted kind changes back to an ordinary task and its legacy NeedsUser flag is removed.
- **Epic** (`kind: epic`, newly created IDs `WTE-####`) is a coordination container: scope, designs, requirements, notes and subtask progress. **Epics do not have acceptance criteria, AI Notes, card icons, question/attention flags, hard dependencies or a parent.** Their editor instead exposes a dedicated planning/coordination Notes field. Epics cannot be claimed or assigned. **Dragging an epic to a column moves all its unfinished descendant tasks there** (agent-claimed tasks stay put; moving to Done asks first; one Undo restores all). Their column is derived from descendant executable tasks (In Progress takes priority; all completed => Done; entirely blocked/waiting => Blocked; otherwise the most active ready work column). A new epic with no children stays Draft.
- Existing epic IDs retain their historical `WT-####` identifier for compatibility with code, docs and agents; they still get a distinctive purple epic card (without a redundant EPIC badge), non-executable behavior and progress tracker.
- **Cross-column epic proxies:** When descendants are visible in a column other than their nearest epic ancestor, TaskBoard renders a **thin purple epic proxy** (without an EPIC badge) just above each contiguous group of those descendants. Hovering the proxy highlights the one real epic card and its column; clicking jumps to the real card (or opens it if its column is intentionally hidden). Proxies are visual references only: no duplicate task records, claims, status changes, or drag handles. They respect search, collapsed descendants and dependency ordering.
- **Collapse epics:** Each epic has a collapse/expand chevron; the toolbar has **Collapse all epics / Expand all epics**. Folding hides ordinary descendants across all columns, including while searching, while **orange For user cards always remain visible**. Fold state is stored locally and actions support Undo. Cross-column epic proxies remain for visible orange tasks.
- **Done archive by age:** Right-click a terminal/Done column and choose **Archive older than 3 days**. This archives only cards with an actual `completed_at` timestamp at least 72 hours old. Recently completed, undated and still-active epic cards are preserved; younger children are never detached just to archive a parent. The action checks revisions under a write lock and supports Undo. The existing **Archive all** remains separate.
- Each executable task can declare `depends_on: [task ID, ...]` (hard prerequisite) and `related_to: [task ID, epic ID, ...]` (informational), including existing legacy IDs and new board prefixes. Enforced by shared Rust core: no claiming or starting an unfinished prerequisite's dependent, no dangling/self/duplicate links, no hard dependency cycles, and no hard dependency on an epic. Completion/archiving satisfies a prerequisite; reopening makes dependents wait again.
- In the task editor, the **Task / Epic** selector is at the top (with a separate orange For user toggle for ordinary cards). Only executable/user tasks get an optional parent dropdown, containing epics exclusively. Dropping a task onto an epic makes it a child. **Dropping a task onto another ordinary task places it directly below that card in the target column**, without changing the hierarchy. The placement is persisted in task frontmatter as `position_after`/`positioned_at`, and hard dependencies still take precedence. Tasks expose Ready, Waiting and Blocked states separately from their columns. The app edits dependency links using searchable multi-select task pickers (search by ID or title), and shows clickable links in hover previews. **Directional red prerequisite-to-dependent lines** connect only *unfinished* visible prerequisites to their dependents, never from Done cards. Once every dependency is complete, an ordinary task in Blocked automatically returns to AI Ready (or In Progress when already agent-claimed); explicit Blocked attention and human-only tasks remain blocked. They are drawn in an independent pointer-transparent SVG overlay, never reserve layout space, track scrolling/resizing, and are visually occluded behind unrelated intermediate columns. The column uses a stable topological ordering so a dependency always appears above the task it gates; unrelated tasks retain their normal sort order, and epic parents remain above their displayed children. `task list --ai-ready` excludes epics, tasks with unfinished dependencies and explicitly blocked tasks.
- CLI usage: `task create --kind epic --title "Work stream"`, `task create --depends-on WT-0012 --related-to WT-0015 ...`, `task update WT-0034 --depends-on WT-0012 --related-to WT-0015`, `task update WT-0034 --clear-dependencies`; `task show` includes `readiness`, `waiting_for`, `blocks` and `epic_progress`.
- Only declare hard dependencies when the **entire task cannot meaningfully begin**. Use `related_to` for partially shared work or cross-functional coordination to avoid unnecessarily serializing autonomous agents.

## Human visual reviews

**Review** next to **Board** opens a live human-feedback queue for the current project; check **All boards** to see pending reviews from other tabs. Agents request reviews through `task review request --mode pick|approve|rank|markup --judge ... --artifact path=label`. Candidates, references and poster previews sync in each board's `Tasks/Reviews/<ID>/`; >25 MB media stays in a local cache with a synced poster. The request raises a Question attention marker. The human can choose variants, compare before/after via slider/overlay, rank them, place timestamped/normalized pins, write feedback, reject or ask for more variants. ## Review retention and GC

Review media uses manifest timestamps for stateless retention: losing variants (including superseded/rejected rounds) become eligible after 48 hours, while chosen/approved variants remain until the implementing task archives. At archive, GC creates a `receipt.webp` no larger than 200 KB and recycles the large winner media and `refs/`. Receipt and manifest expire after 90 days. Open rounds are never automatically pruned; TaskBoard flags open requests older than 30 days. Orphan local-only cache directories expire after 7 days. Reopening the implementing task clears pending archive expiry. These are **due times**: files are moved to the **Windows Recycle Bin** on the next sweep, never permanently deleted by TaskBoard. Each recycle/receipt action is logged in `Reviews/_gc.log`.

Preview with `TaskBoard.exe --root "<board>/Tasks" --json task review gc --dry-run`. Run one board with `--json task review gc` or all registered boards with `--json task review gc --all-boards`. `--all-boards` reads `%APPDATA%\TaskBoard\projects.json`; boards that are not mounted are skipped. Desktop TaskBoard starts a low-priority sweep at startup and every six hours. The Windows scheduled task **TaskBoard Review GC** independently runs at login and 03:30 daily through an invisible WScript launcher (`scripts/TaskBoardReviewGc.vbs`) to avoid console flashes. Install/re-register with `scripts/Install-TaskBoardReviewGc.ps1`, remove with `scripts/Install-TaskBoardReviewGc.ps1 -Uninstall`. Both entrypoints take the TaskBoard per-board mutation lock. Sync data above 1 GB produces a warning, not a write refusal.

### Reconcile previously completed implementation reviews

Use `task review reconcile-linked` with the relevant `--root` to **preview**
completed, explicitly linked implementation-review cards that have not yet been
applied to their source tasks. This is read-only by default. After checking
the report, run `task review reconcile-linked --apply` to reconcile only
eligible reviews. Ambiguous answers do not approve source tasks; the source
retains an audit entry rather than silently completing. Ordinary For User
cards and reviews with ambiguous relationships are excluded. Do not run
`--apply` against production boards without inspecting the preview first.
